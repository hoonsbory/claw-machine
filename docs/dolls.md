# 인형 바꿔 넣기

이 문서는 게임에 나오는 인형을 바꾸거나 고치는 방법을 적은 안내서다. 지금은 실제로 선물할 인형 5종(쿠리만쥬·시사·카니·하치와레·우사기)의 3D 모델이 들어 있다.
게임 코드는 고치지 않는다. `public/dolls/` 에 모델 파일을 넣고 `src/config/dollCatalog.ts` 한 곳만 고친다.

## 1. 먼저 알아 둘 것

### 모양과 충돌 도형은 따로 있다

- 화면에 보이는 모양은 `.glb` 모델 파일이다.
- 물리 계산과 집게 판정은 모델의 실제 모양을 쓰지 않는다. 설정에 적은 단순한 공(필요하면 캡슐) 몇 개로 계산한다. 이것을 충돌 도형이라고 부른다. 모델이 복잡해도 물리가 무거워지지 않는 이유다.
- 그래서 모델을 넣은 뒤에는 충돌 도형이 모델과 대략 겹치도록 치수를 맞춰야 한다.

### 크기는 두 단계로 정해진다

1. 게임이 모델을 "표준 크기"로 맞춘다. 파일 안의 원래 크기나 원점이 어떻든, 모델 전체 높이를 1.5 로 늘리거나 줄이고 바닥 가운데를 모델 바닥 높이(`modelBaseY`, 적지 않으면 몸통 공의 아래 끝)에 놓는다. 이 단계는 게임이 알아서 하므로 따로 할 일이 없다.
2. 그다음 `scale` 을 모양과 충돌 도형에 함께 곱한다. `scale` 이 인형끼리의 실물 크기 비율을 정한다.

`coreRadius`, `modelBaseY` 와 충돌 도형(`colliders`)의 치수는 `scale` 을 곱하기 전의 표준 크기 단위로 적는다. 모델 높이를 1.5 로 보고 재면 된다.

### scale 정하는 기준

- 실물 인형은 작은 것이 높이 12cm 쯤, 큰 것이 20~25cm 쯤이다. 게임도 이 비율을 `scale` 로 그대로 살린다.
- `scale` 은 **실물 높이(cm) ÷ 17** 로 정한다. 12cm 는 0.7, 17cm 는 1.0, 20cm 는 1.2, 24cm 는 1.4 쯤이 된다.
- 지금 들어 있는 인형은 큰 것(쿠리만쥬·시사·카니, 20~25cm)이 모두 1.25, 작은 마스코트 인형(하치와레·우사기, 약 12cm)이 그 절반쯤인 0.65 다.
- 높이는 인형을 앉힌 자세로 바닥부터 가장 높은 곳(귀나 장식 포함)까지 잰다. 게임이 모델 전체 높이를 표준 크기로 맞추기 때문에 같은 기준으로 재야 비율이 맞는다.
- 집게 손가락 크기와 배출구 크기는 가장 큰 몸통 공(아래 4장의 첫 공)에 맞춰 자동으로 정해진다. 따로 고칠 곳은 없다.
- 지금의 집게 힘과 닿는 여유는 몸통 반지름(`coreRadius × scale`)이 0.35~0.7 쯤인 인형으로 맞춰 둔 값이다. 이 범위를 크게 벗어나는 인형이 있으면 난이도를 다시 맞춰야 한다. 지금 인형 중 하치와레(약 0.16)와 우사기(약 0.31)는 이 범위보다 작아서 집게를 더 정확히 맞춰야 잡힌다. 직접 해 보고 유독 어려우면 그 종류에만 `tuning` 을 덮어쓴다(아래 4장).

## 2. 준비물

- 인형 한 종류마다 `.glb`(glTF 바이너리) 파일 하나.
- 폰에서 끊기지 않도록 파일 하나에 **삼각형 2만 개 이하, 파일 크기 2MB 이하**를 권장한다. 사진으로 3D 를 만드는 서비스가 내놓는 파일은 이보다 훨씬 무거우므로 아래 "무거운 모델 줄이기" 대로 줄여서 넣는다. 줄이는 도구가 처리하면서 줄이기 전과 뒤의 삼각형 수, 결과 파일 크기를 보여 준다. 파일 크기는 Finder 에서도 볼 수 있다.
- 모델에는 인형만 남긴다. 받침대·바닥판이나 떨어져 떠 있는 작은 조각이 붙어 있으면 게임이 그것까지 높이로 재어 인형이 작게 보이거나 바닥에서 떠 보인다. 사진으로 만든 모델에는 이런 조각이 자주 따라오므로 내보내기 전에 지운다.
- Draco(메시 압축)와 KTX2(텍스처 압축)는 끄고 내보낸다. KTX2 텍스처는 게임이 읽지 못하고, Draco 는 열 때마다 다른 사이트(구글 서버)에서 해독기를 받아 와야 해서 느리거나 막힐 수 있다.
- 모델은 위쪽이 +Y 여야 한다. glTF 의 기본 방향이라 대부분의 도구가 이렇게 내보낸다. 게임에서 인형이 누워 있거나 거꾸로 보이면 도구에서 방향을 고쳐 다시 내보낸다.
- 얼굴은 +Z 쪽(glTF 의 기본 앞쪽)을 보면 좋다. 축하 화면에서 인형이 천천히 돌기 때문에 꼭 맞추지 않아도 되지만, 움직임 줄이기를 켠 폰에서는 인형이 돌지 않고 이 방향으로 서 있다.
- 실물 인형의 높이(cm).

### 무거운 모델 줄이기 (`npm run shrink-glb`)

사진으로 만든 모델은 그대로 넣으면 폰이 버티지 못한다. 지금 인형들의 원본은 파일 하나가 약 70MB, 삼각형 약 150만 개에 4K PNG 텍스처가 세 장씩 들어 있었다. 저장소에 들어 있는 줄이는 도구로 폰용 파일을 만든다.

```
npm run shrink-glb -- <원본.glb> public/dolls/<id>.glb [목표 삼각형 수=16000] [텍스처 한 변=1024]
```

- 예: `npm run shrink-glb -- 쿠리만쥬.glb public/dolls/kurimanju.glb`. 뒤의 두 값을 빼면 삼각형 16,000 개, 텍스처 한 변 1024 픽셀로 줄인다.
- **삼각형은 16,000 개를 권한다.** 10,000 개로 줄였을 때는 텍스처 이음매를 따라 줄무늬가 보였고, 16,000 개에서는 깨끗했다. 결과 파일은 약 0.8MB 다.
- 남기는 것: 기본 색 텍스처와 노멀 맵(천의 결). 둘 다 한 변 1024 픽셀 JPEG 로 줄인다.
- 버리는 것: 금속성·거칠기 맵. 천 인형이라 금속성 0, 거칠기 1 로 둔다.
- 처리하는 동안 원본과 결과의 삼각형 수, 결과 파일 크기(KB)를 보여 준다. 이미 줄인 파일의 삼각형 수만 보고 싶을 때도 `npm run shrink-glb -- public/dolls/<id>.glb 확인용.glb` 처럼 돌려 첫 줄을 보고, 만들어진 `확인용.glb` 는 지운다.
- **macOS 에서만 돈다.** 텍스처를 macOS 에 들어 있는 `sips` 로 줄이기 때문이다.
- 메시 하나에 조각 하나짜리 모델(사진으로 3D 를 만드는 서비스가 보통 내놓는 모양)만 다룬다. Draco 로 압축했거나 여러 조각으로 된 파일이면 이유를 보여 주고 멈춘다.
- 원본의 방향(위가 +Y)은 그대로 둔다. 줄인 뒤에는 아래 3장대로 게임에서 모양과 방향을 확인한다.
- 무거운 원본은 저장소 맨 위에 두어도 된다. `.gitignore` 가 맨 위의 `.glb`·`.webp` 를 빼 두어서 실수로 올라가지 않는다. 올리는 것은 `public/dolls/` 의 줄인 파일뿐이다.

## 3. 넣는 순서

1. 모델 파일 이름을 종류 id 로 정해 `public/dolls/<id>.glb` 에 넣는다. 예를 들어 `public/dolls/kurimanju.glb` 다. 무거운 원본이면 위의 "무거운 모델 줄이기" 로 이 자리에 바로 만든다. id 는 영어 소문자로 짓고 종류마다 달라야 한다. 빌드하면 이 파일들이 `dist/dolls/` 로 그대로 복사된다. `dist` 폴더는 정적 호스팅의 맨 위에 올려도, 하위 경로(예: `https://주소/secret-path/`)에 올려도 그대로 동작한다. 하위 경로에 올렸다면 넘겨줄 주소는 반드시 `/` 로 끝나게 한다. `https://주소/secret-path` 처럼 `/` 없이 열면 호스팅에 따라 `불러오는 중…` 에서 멈춘다.
2. `src/config/dollCatalog.ts` 의 `DOLL_KINDS` 에서 바꿀 종류 하나를 고친다.
   - `id`: 파일 이름과 같은 id. 뽑은 기록에 이 id 가 저장된다.
   - `displayName`: 축하 화면에 크게 나오는 이름.
   - `modelUrl`: `'dolls/<id>.glb'`. 앞에 `/` 를 붙이지 않는 `public/` 기준 상대 경로다. 게임이 앱이 놓인 경로를 앞에 붙여 읽으므로 하위 경로에 올려도 모델을 찾는다.
   - `scale`: 실물 높이(cm) ÷ 17.
   - `placeholder`: 모델을 읽는 동안이나 읽지 못했을 때 대신 보일 임시 도형이다. 생김새(`look`)는 다섯 가지 중에서 고르고, 색은 실제 인형과 비슷하게 둔다.
   - `coreRadius`, `modelBaseY`, `colliders`: 처음에는 생김새가 비슷한 지금 종류의 값을 베껴 두고 5번에서 맞춘다. `modelBaseY` 는 몸통 공을 머리에 둘 때만 적는다(아래 4장).
3. 개발 서버를 켜고(`npm run dev`) 주소 끝에 `?debug` 를 붙여 연다. 예: `http://localhost:5173/?debug`
4. 모델이 보이는지 확인한다. 임시 도형만 보이면 모델을 읽지 못한 것이다. 브라우저 콘솔에 `Could not load /dolls/<id>.glb` 오류(빌드 결과물에서는 `./dolls/<id>.glb`)가 있는지 보고, 파일 이름과 `modelUrl` 이 같은지 확인한다. 모델을 읽지 못해도 그 종류만 임시 도형이 되고 게임은 계속된다.
5. 충돌 도형을 맞춘다(아래 4장).
6. 조정 패널로 집게 힘을 맞추고, 정한 값을 `src/config/gameConfig.ts` 에 적는다(아래 5장).
7. `?reset` 을 붙여 기록을 지우고 처음부터 한 판을 끝까지 돌려 본다(아래 6장).
8. `npm run verify` 와 `npm run build` 가 둘 다 통과하는지 확인한다. 종류·`scale`·집게 힘을 바꿨다고 깨지는 테스트는 없다. `verify` 가 실패하면 `src/config/dollCatalog.test.ts` 의 실패 메시지가 카탈로그나 설정에서 고칠 곳을 알려 준다.

종류 수는 5가 아니어도 된다. `DOLL_KINDS` 에 적은 개수가 화면 위 `0 / 5` 의 전체 수가 된다. 다만 종류마다 4개씩(`gameConfig.ts` 의 `dolls.perKind`) 들어가므로 종류가 많아지면 기계 안이 붐빈다. 지금은 5종 × 4개로 모두 20개다.

### 예시

지금 들어 있는 쿠리만쥬(실물 20~25cm)다. 작은 몸통 위에 큰 머리가 얹힌 모양이라 집게가 감싸는 첫 공을 머리에 두고, 모델 바닥을 그 아래로 내렸다.

```ts
{
  id: 'kurimanju',
  displayName: '쿠리만쥬',
  modelUrl: 'dolls/kurimanju.glb',
  placeholder: { look: 'bear', color: '#f3d7b0' },
  scale: 1.25, // 큰 인형 셋이 같이 쓰는 값(약 21cm ÷ 17)
  coreRadius: 0.45,
  modelBaseY: -1.05, // 머리 가운데에서 발끝까지 1.05 아래(모델 높이 1.5 기준)
  colliders: [
    { shape: 'ball', radius: 0.45, offset: [0, 0, 0] }, // 머리: 원점, 반지름은 coreRadius 와 같게
    { shape: 'ball', radius: 0.33, offset: [0, -0.72, 0.03] }, // 몸통: 아래 끝이 modelBaseY 에 닿게
    { shape: 'ball', radius: 0.3, offset: [-0.28, -0.05, 0] }, // 머리 왼쪽(머리가 옆으로 넓다)
    { shape: 'ball', radius: 0.3, offset: [0.28, -0.05, 0] }, // 머리 오른쪽
  ],
},
```

## 4. 충돌 도형 맞추기

- `?debug` 로 열면 충돌 도형이 선으로 그려진다. 공은 둥근 선 몇 줄로 보인다. 모델 안에 들어간 선은 모델에 가려지므로, 선이 모델 밖으로 크게 드러나 보이면 그 공이 너무 크거나 자리가 어긋난 것이다. 이 선은 `?debug` 일 때만 보인다.
- **몸통 공**(첫 공)은 집게가 감싸는 공이다. 원점(`offset: [0, 0, 0]`)에 두고, 반지름은 `coreRadius` 와 같은 값으로 적는다.
  - 집게가 멈추는 높이, 잡힌 인형이 매달리는 위치(집게 몸통 바로 아래), 닿는 범위가 모두 이 공을 기준으로 계산된다.
  - 보통은 인형의 몸통(가장 아랫부분)에 둔다. 모델 바닥은 `modelBaseY` 를 적지 않으면 이 공의 아래 끝에 맞춰지므로, `coreRadius` 를 바꾸면 모델이 공과 함께 오르내린다.
  - **머리가 몸통보다 큰 인형은 머리에 둔다.** 몸통에 두면 집게가 머리 속까지 내려가 멈추고, 들고 갈 때 집게 몸통이 머리를 뚫고 보인다. 지금 인형 다섯은 모두 머리(하치와레는 별 가운데)에 두었다.
  - 머리에 두었으면 `modelBaseY` 에 머리 가운데에서 발끝까지의 거리를 음수로 적는다(표준 크기 단위). 예: 쿠리만쥬 `-1.05`. 모델 바닥이 그 높이에 놓이고, 배출구 판정도 이 높이로 "똑바로 선 높이"를 계산해서 배출구 바닥에 서 있는 인형을 들어간 것으로 친다.
  - 공이 덮을 덩어리보다 많이 작으면 반지름을 늘리고, 많이 크면 줄인다.
- **나머지 공**은 몸통이나 머리 양옆처럼 큰 덩어리 가운데에 오도록 `offset`(가로, 높이, 앞뒤)과 `radius` 를 고친다. 몸통 공을 머리에 두었다면 아래쪽 몸통 공의 아래 끝이 `modelBaseY` 에 닿게 둔다. 그래야 똑바로 섰을 때 바닥에 뜨거나 묻히지 않는다.
- 작은 귀나 팔까지 덮을 필요는 없다. 충돌 도형은 인형끼리 부딪히고 쌓이는 모양만 정한다. 다만 시사의 갈기나 우사기의 늘어진 귀처럼 크게 튀어나온 곳은 작은 공으로 덮어, 옆 인형이 그 속으로 파고들어 보이지 않게 한다.
- 납작한 인형(하치와레 같은 별 모양)은 두께의 절반쯤 되는 작은 공 몇 개로 모양을 따라 덮는다. 큰 공 하나로 덮으면 누웠을 때 바닥에서 떠 보인다.
- 길쭉한 부분이 있으면 캡슐(`shape: 'capsule'`, `halfHeight`, `radius`)도 쓸 수 있다. 캡슐은 늘 위아래로 선다(하치와레의 별 위 끝에서 발까지를 캡슐 하나로 덮었다).
- 충돌 도형은 종류마다 네 개 이하로 둔다. 폰에서 물리 계산이 가볍게 돈다.
- 어떤 종류만 유독 어렵거나 쉬우면 그 종류에 `tuning: { grip: 0.7 }` 처럼 덮어쓴다. 이렇게 덮어쓴 종류에는 조정 패널의 같은 값이 적용되지 않는다.

## 5. 조정 패널 (`?debug`)

- 주소 끝에 `?debug` 를 붙이면 왼쪽 위에 `조정` 버튼이 생긴다. 누르면 펼쳐지고, 다시 누르면 접힌다.
- **집게 힘**(0~1): 클수록 끝까지 잘 들고 간다. 집게 가운데에 인형이 가까울수록 더 잘 든다.
- **닿는 여유**(0.1~0.8): 몸통 가장자리에서 이만큼 떨어진 곳에 내려도 잡을 수 있다.
- **보정까지 실패 횟수**(1~6): 이만큼 연속으로 실패하면, 다음 시도는 어느 정도만 맞혀도 끝까지 들고 간다.
- **연속 실패**: 지금 몇 번 연속으로 실패했는지 보여 준다. 뽑으면 0 이 된다.
- **기록 저장**: 이 기기(이 브라우저)에서 뽑은 기록을 저장할 수 있으면 `가능`, 아니면 `불가` 다. `불가` 면 새로고침할 때 뽑은 인형이 기계에 다시 나온다. 사생활 보호(시크릿) 탭은 `가능` 으로 나와도 탭을 닫으면 기록이 사라진다.
- 바꾼 값은 다음 시도부터 적용된다. 집게가 움직이는 중에 바꾸면 그 시도는 원래 값으로 끝난다.
- 바꾼 값은 저장되지 않아서 새로고침하면 사라진다. 마음에 드는 값을 찾으면 `src/config/gameConfig.ts` 의 `grab.grip`(집게 힘), `grab.reachMargin`(닿는 여유), `grab.pityAfterFails`(보정까지 실패 횟수)에 직접 적는다.
- 슬라이더는 손가락이나 마우스로 끈다. 방향키는 슬라이더를 만진 뒤에도 늘 집게를 움직인다.

## 6. 기록 지우기 (`?reset`)

- 뽑은 기록은 그 폰(그 브라우저)에만 저장된다.
- 주소 끝에 `?reset` 을 붙여 열면 그 폰의 기록이 지워지고 모든 인형이 다시 들어간 상태로 시작한다. 다른 폰의 기록은 그대로다.
- 주소에서 `reset` 은 열자마자 사라지므로, 그 뒤에 새로고침해도 다시 지워지지 않는다.
- 축하 화면을 닫기 전에 새로고침되거나 탭이 닫혀도(사진을 찍으러 카메라 앱에 갔다 오는 사이 등) 다시 열면 그 축하 화면부터 다시 뜬다. `?reset` 은 이 기록도 함께 지운다.
- `?debug&reset` 처럼 함께 써도 된다.
- 종류의 `id` 를 바꾸면 예전 id 로 저장된 기록은 무시된다.

## 7. 선물 전 확인 목록

- [ ] 모든 종류가 임시 도형이 아니라 모델로 보인다.
- [ ] 브라우저 콘솔에 오류가 없다. 특히 `dolls/` 모델 주소가 들어간 `Could not load ...` 가 없다.
- [ ] `?debug` 로 열었을 때 충돌 도형 선이 모델과 대략 겹친다.
- [ ] 정한 집게 힘, 닿는 여유, 보정까지 실패 횟수를 `src/config/gameConfig.ts` 에 적었다.
- [ ] `npm run verify` 와 `npm run build` 가 통과한다.
- [ ] 실제 폰에서 빌드 결과물을 열어 한 판을 끝까지 돌렸다. 모든 종류를 뽑고 마지막 축하 화면(`전부 뽑았다!`)까지 봤다.
- [ ] 실제 폰에서 끊기지 않고 움직인다.
- [ ] 소리를 실제 폰에서 귀로 들어 확인했다. 자동 점검으로는 소리가 실제로 들리는지 확인하지 못했다. 아이폰은 무음 모드에서 소리가 나지 않을 수 있으니 무음을 끄고 듣는다.
- [ ] 안드로이드 폰이라면 잡을 때 짧게, 뽑을 때 길게 떨린다. 아이폰 브라우저에서는 진동이 없다.
- [ ] 주소에 `?debug` 가 없을 때 조정 패널과 충돌 도형 선이 보이지 않는다.
- [ ] 선물할 폰에서, 선물할 때 쓸 바로 그 브라우저로 기록이 남는지 확인했다. 인형 하나를 뽑고 축하 화면이 떠 있는 채로 새로고침하면 그 축하 화면이 다시 뜬다. 닫은 뒤 새로고침하고, 탭을 닫았다가 다시 열어도 뽑은 종류가 기계에 다시 나오지 않고 축하 화면도 다시 뜨지 않는다. 사생활 보호(시크릿) 탭이나 카카오톡 같은 메신저 안에서 열리는 브라우저로는 하지 않는다(탭을 닫으면 기록이 사라지거나, 다음에 다른 브라우저로 열려 기록이 없다). `?debug` 를 붙여 열고 `조정` 을 펼치면 `기록 저장` 줄에 이 기기에서 저장할 수 있는지 나온다. 확인이 끝나면 `?reset` 을 붙여 다시 열어 기록을 지운다.
- [ ] 선물할 폰으로 시험해 봤다면 `?reset` 을 붙여 한 번 열어 기록을 지웠다. 넘기는 주소에는 `?reset` 도 `?debug` 도 붙이지 않는다.
- [ ] 기록을 지운 상태에서 새로 열고 아무것도 누르지 않은 채 기다려도 축하 화면이 뜨지 않는다(닫지 않은 축하 화면이 남아 있었다면 그것은 다시 뜨는 것이 맞다). 처음 내리기를 누르기 전에 배출구에 굴러 들어간 인형은 뽑은 것으로 치지 않고 위에서 다시 떨어뜨린다. 첫 내리기 뒤에는 굴러 들어간 인형도 뽑은 것으로 친다.
