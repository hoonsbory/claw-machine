# 인형뽑기 선물 게임 설계

> 작성일 2026-11-11 · 상태: 검토 대기
> 표기: **[결정]** 은 의뢰인이 직접 정한 것, **[내 판단]** 은 작성자가 기본값으로 정한 것(바꿔도 됨), **[만드는 사람]** 은 구현자가 정하면 되는 것.

## 1. 무엇을, 왜

인형을 좋아하는 여자친구에게 줄 선물이다. 실제 인형 5종류를 준비하고, 그 인형들을 본뜬 3D 인형뽑기 웹 게임을 만든다. 여자친구가 게임에서 뽑은 인형을 그 자리에서 실물로 건네준다.

선물의 핵심은 "화면에서 내가 뽑은 인형을 진짜로 받는다"는 연결이다. 게임은 그 순간을 만들기 위한 도구이고, 말과 건네기는 옆에 있는 의뢰인이 직접 한다.

### 플레이 장면 [결정]

- 두 사람이 같이 있는 자리에서, 의뢰인이 주소를 열어 건넨 폰으로 여자친구가 플레이한다.
- 한 자리에서 5종류를 모두 뽑는 흐름을 예상한다. **[내 판단]**
- 플레이하는 사람은 여자친구 한 명뿐이다.

## 2. 목표와 목표가 아닌 것

### 목표

- 폰 세로 화면에서 터치로 조작하는 3D 인형뽑기.
- 기계 안 인형이 실제 선물 인형과 닮아서, 뽑은 것이 무엇인지 바로 알 수 있다.
- 조준하고 집고 들어 올리는 과정에 긴장과 손맛이 있다.
- 결국에는 5종류를 모두 뽑게 된다.

### 만들지 않는 것 [결정]

- 인형마다 붙는 메시지 카드, 다 뽑은 뒤의 편지·마무리 화면, 뽑은 인형 모음 화면.
- 쿠지·가챠 방식.
- 선물이 아닌 꽝 인형.

### 만들지 않는 것 [내 판단]

- 로그인, 서버, 여러 사람용 기능, 점수·순위.
- 여자친구에게 보이는 난이도 조정 화면.

### 이렇게 되면 실패

- 끝내 못 뽑아서 자리 분위기가 식는다.
- 폰에서 버벅이거나 조작이 손가락에 안 붙는다.
- 뽑았는데 그게 어떤 인형인지 헷갈린다.
- 새로고침이나 실수로 닫았을 때 뽑은 기록이 사라져 이미 받은 인형이 다시 기계에 나온다.

## 3. 게임 규칙

### 기계 안 [결정]

- 인형은 5종류이고, 종류마다 여러 개씩 넣어 기계를 채운다.
- 한 종류를 뽑으면 기계에 남아 있는 같은 종류가 모두 사라진다. 중복은 생기지 않고, 성공 5번이면 5종류를 다 모은다.
- 실물은 종류당 1개만 준비한다.

### 기계 안 [내 판단]

- 종류당 3개, 모두 15개로 시작한다. 폰에서 버벅이거나 너무 빽빽하면 줄인다. 설정값 하나로 바꿀 수 있어야 한다.
- 같은 종류가 사라질 때는 뿅 하고 작아지며 없어지는 짧은 연출을 넣는다. 사라진 자리 위에 있던 인형은 자연스럽게 내려앉는다.

### 한 번의 시도

시제품에서 확인하고 의뢰인이 "방향은 이대로 좋다"고 한 흐름이다. **[결정]**

1. 대기: 조이스틱으로 집게를 앞뒤·좌우로 움직인다. 집게는 줄에 매달린 것처럼 살짝 늦게 따라오며 흔들린다. 집게 바로 아래 바닥에 위치 안내선이 보인다.
2. 내리기 버튼을 누르면 집게가 내려간다. 아래에 인형이 있으면 그 위에서, 없으면 바닥 근처에서 멈춘다.
3. 집게가 오므라든다. 닿는 범위에 인형이 있으면 가장 가까운 하나를 잡는다.
4. 들어 올린 뒤 배출구(앞쪽 왼편 구석) 위로 옮긴다.
5. 집게를 벌려 인형을 떨어뜨린다. 인형이 배출구 안에 들어가면 획득이다.
6. 집게가 대기 상태로 돌아온다. 시도 중에는 조작이 잠긴다.

배출구는 낮은 칸막이로 둘러싸여 있어 인형이 굴러서 들어가기는 어렵다. 굴러서 들어간 경우에도 획득으로 친다. **[내 판단]**

### 집기 판정 [결정: 방식 / 내 판단: 수치]

집게 손가락이 인형을 물리적으로 쥐는 방식이 아니라 판정 방식이다. 난이도를 마음대로 조절하기 위해서다.

- 집게 중심에서 인형 중심까지의 수평 거리가 가까울수록 잘 잡은 것이다.
- 잡는 순간에 "끝까지 들고 갈지"가 정해진다. 잘 잡을수록, 집게 힘 설정이 클수록 성공한다.
- 실패로 정해진 경우 들어 올리거나 옮기는 도중에 인형이 조금씩 처지다가 떨어진다. 떨어진 인형은 그 자리에 물리적으로 굴러 내려앉는다.
- **보정**: 연속으로 3번 실패하면, 다음에 인형을 어느 정도라도 잡았을 때는 반드시 끝까지 들고 간다. "이렇게 되면 실패"의 첫 항목을 막는 장치이므로 항상 켜 둔다.
- **보정의 한계 [결정]**: 도움 장치는 이 보정 하나로 충분하다. 계속 허공을 집는 경우나, 들고 갔는데 배출구 칸막이에 튕겨 나오는 경우까지 자동으로 막지는 않는다. 실패가 쌓일 때 닿는 범위를 넓히거나 배출구로 강제로 넣는 규칙은 만들지 않는다. 이런 상황은 의뢰인이 집게 힘과 닿는 범위를 넉넉하게 맞춰서 피한다.
- 집게 힘, 닿는 범위, 보정까지의 횟수는 한 곳에 모은 설정값이다. 시작값은 시제품(`spike/claw-feel/main.js`)의 값을 쓰고, 실제 인형 모양이 들어온 뒤 의뢰인이 직접 플레이해 보며 다시 맞춘다.

### 뽑은 순간 [결정]

- 축하 연출만 한다: 뽑은 인형이 화면에 크게 떠오르고 폭죽(색종이)이 터진다. 화면을 누르면 닫히고 게임으로 돌아간다.
- 5종류를 모두 뽑으면 같은 축하 연출을 더 크게 한 번 하고, 빈 기계가 남는다. 따로 마무리 화면은 없다.

### 진행 저장 [내 판단]

- 뽑은 종류는 그 폰의 브라우저 저장소에 기록한다. 새로고침하거나 닫았다 열어도 이미 뽑은 종류는 기계에 나오지 않는다.
- 의뢰인이 미리 시험해 본 뒤 처음 상태로 되돌릴 수 있어야 한다. 주소 뒤에 `?reset` 을 붙여 열면 기록을 지우고 처음부터 시작한다. 화면에는 초기화 버튼을 두지 않는다.

## 4. 화면과 조작

### 기준 기기 [결정]

- 폰 세로 화면과 터치가 기준이다.
- 노트북에서는 화면 가운데에 세로 비율 기계가 뜨고, 방향키로 이동하고 스페이스로 내린다. 따로 가로 화면 배치는 만들지 않는다.

### 화면 구성 [내 판단]

- 화면 위쪽 대부분은 3D 기계다. 정면 약간 위에서 내려다보는 고정 시점이고, 플레이어가 시점을 돌릴 수 없다.
- 왼쪽 아래에 조이스틱, 오른쪽 아래에 큰 내리기 버튼이 있다. 조작부가 기계 바닥을 가리지 않는다.
- 위쪽에 뽑은 종류 수(예: 2 / 5)를 작게 보여 준다.
- 소리 켜고 끄는 버튼이 하나 있다.
- 분위기는 시제품과 같은 파스텔 분홍 계열의 귀여운 기계다. 특정 기존 게임이나 브랜드의 생김새를 따라 하지 않는다.

### 소리와 진동 [내 판단]

- 내리기, 잡기, 미끄러짐, 획득에 효과음이 있다. 배경 음악은 없다.
- 진동은 지원하는 기기(안드로이드)에서만 쓴다. 아이폰 브라우저는 진동이 안 되므로 소리와 화면 연출만으로도 충분해야 한다.

## 5. 인형

### 지금 상태 [결정]

- 어떤 인형을 줄지 아직 정하지 않았다. 완성 기한도 없다.
- 그래서 임시 인형으로 게임을 먼저 완성하고, 실제 인형이 정해지면 갈아 끼운다.

### 크기 [결정: 실물 치수 / 내 판단: 다루는 방식]

- 실물 인형은 크기가 조금씩 다르다. 작은 것은 높이 12cm쯤, 큰 것은 20~25cm쯤이다. 가장 큰 것이 가장 작은 것의 두 배 안팎이다.
- 게임 안에서도 이 비율을 살린다. 큰 인형은 크게, 작은 인형은 작게 보인다.
- 그래서 집게가 멈추는 높이, 잡힌 인형이 매달리는 위치, 집게가 막히는 범위는 전역 상수가 아니라 종류별 충돌 도형 치수에서 계산한다.
- 집게 벌어진 폭과 배출구 크기는 가장 큰 인형이 여유 있게 들어가도록 정한다. 가장 큰 인형의 치수가 바뀌면 설정값만 고쳐서 맞출 수 있어야 한다.
- 집게 힘 같은 난이도 수치는 모든 종류에 공통으로 두되, 특정 종류만 따로 덮어쓸 수 있게 한다. 크기 때문에 어떤 종류만 유독 어렵거나 쉬울 때 쓴다.
- 임시 인형 5종도 이 범위(가장 큰 것이 가장 작은 것의 두 배쯤)로 크기를 다르게 만들어서, 크기 차이가 있는 상태로 손맛을 확인할 수 있게 한다.

### 갈아 끼우는 구조 [내 판단]

- 인형 한 종류는 "3D 모델 파일 하나 + 설정 한 묶음"이다. 설정에는 식별 이름, 화면에 보일 이름, 크기 배율, 충돌용 단순 도형(구나 캡슐 조합)의 치수가 들어간다.
- 충돌은 모델의 실제 모양이 아니라 설정에 적힌 단순 도형으로 계산한다. 모델이 복잡해도 물리가 무거워지지 않는다.
- 종류를 바꾸거나 고치는 일은 모델 파일을 넣고 설정 파일 한 곳을 고치는 것으로 끝나야 한다. 게임 코드를 건드릴 필요가 없어야 한다.
- 임시 인형 5종은 색과 모양이 서로 뚜렷이 다른 단순한 동물로 만든다(코드로 만든 도형이어도 되고 모델 파일이어도 된다 **[만드는 사람]**). 임시 인형도 같은 설정 구조를 거쳐 들어가야 한다.
- 모델 파일 형식은 glTF 바이너리(`.glb`)다. 폰 성능을 위해 종류당 삼각형 2만 개 이하, 파일 2MB 이하를 권장 기준으로 문서에 적어 둔다.

### 이 설계의 범위 밖

- 실제 인형을 3D 모델로 만드는 작업 자체. 인형이 정해진 뒤 따로 진행한다(실물 사진으로 3D를 생성하는 도구를 쓸 예정). 이 설계는 완성된 `.glb` 를 받아 넣는 자리까지만 책임진다.
- 다만 "모델 파일을 받았을 때 어떻게 넣고 크기와 충돌 도형을 맞추는지"를 적은 짧은 안내 문서는 이 프로젝트에 포함한다.

## 6. 만드는 방법

### 기술 구성 [결정]

- Vite, React, TypeScript.
- 3D는 react-three-fiber.
- 화면 UI(조이스틱, 버튼, 축하 화면)는 React와 Emotion의 `css`.

### 기술 구성 [내 판단]

- 물리 엔진은 Rapier(`@react-three/rapier`)를 먼저 검토한다. 시제품은 cannon-es였지만 버리는 코드라 이어 쓰지 않는다. 라이브러리의 현재 버전과 사용법은 구현 전에 공식 문서로 확인한다. Rapier가 맞지 않으면 다른 엔진을 골라도 된다. **[만드는 사람]**
- 집게의 상태 흐름(대기 → 내리기 → 오므리기 → 올리기 → 옮기기 → 놓기)과 집기 판정, 진행 저장은 React나 3D와 무관한 순수 TypeScript 모듈로 둔다. 화면 없이 단위 테스트할 수 있어야 한다. 확률이 들어가는 부분은 난수를 밖에서 넣어 줄 수 있게 한다.
- 조정 가능한 수치(집게 속도, 힘, 닿는 범위, 보정 횟수, 종류당 개수)는 한 파일에 모은다.
- 개발 중에만 열리는 조정 패널을 둔다(주소에 `?debug` 를 붙였을 때만). 의뢰인이 실제 인형을 넣은 뒤 수치를 맞추는 데 쓴다.

### 코드 규칙

의뢰인의 프론트엔드 기준을 따른다: `any` 금지, 명시적 반환 타입, props는 명시적 interface, Emotion은 `css`(styled 금지), 매직넘버는 이름 붙인 상수, early return, 기능 단위 폴더, 데이터와 UI 분리. 주석과 문서는 한국어, 코드 식별자는 영어.

### 검증 [내 판단]

- 단위 테스트(Vitest): 상태 흐름, 집기 판정(잘 잡을수록 성공, 3번 실패 뒤 보정, 크기가 다른 종류의 멈춤 높이와 매달림 위치), 같은 종류 제거, 진행 저장과 `?reset`.
- 타입 검사와 린트를 한 명령으로 돌릴 수 있게 한다.
- 3D 화면과 손맛은 자동 테스트하지 않는다. 폰 세로 크기 브라우저에서 한 판을 끝까지 돌려 확인하고, 최종적으로 의뢰인이 실제 폰에서 확인한다.
- 성능 기준: 최근 3~4년 내 폰에서 끊김 없이 돌아갈 것. 측정은 실제 폰에서 의뢰인이 체감으로 확인한다.

### 배포

- 서버가 필요 없는 정적 사이트다. 여자친구 폰에서 열 수 있게 정적 호스팅에 올린다.
- 어느 서비스에 올릴지와 주소는 완성 무렵 의뢰인과 정한다. 이 설계에서는 "빌드 결과물을 정적 호스팅에 그대로 올리면 동작한다"까지만 요구한다.
- 검색에 걸리지 않게 하고, 주소는 추측하기 어려운 것으로 한다. **[내 판단]**

## 7. 이미 있는 것

- `spike/claw-feel/` : 손맛 확인용 일회용 시제품(빌드 없는 three.js + cannon-es). 조작 방식, 집게 흔들림, 판정식 집기, 보정, 수치의 시작값을 참고하는 용도다. 본 제작 코드로 가져다 쓰지 않으며, 본 제작이 자리를 잡으면 지운다.

## 8. 만드는 사람에게 맡기는 것

- 폴더 구조와 컴포넌트 분리.
- 물리 엔진의 최종 선택과 세부 설정.
- 기계·집게·임시 인형의 구체적인 생김새(4장의 분위기 안에서).
- 효과음을 합성할지 파일로 넣을지.
- 축하 연출의 구체적인 움직임.
